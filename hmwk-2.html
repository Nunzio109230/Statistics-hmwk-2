03 / The components

What does each standard or primitive do?

Some components are key-management standards; others are mathematical primitives or representation conventions.

🧩
Key generation

BIP-39

Converts random entropy into words with a checksum, then uses the mnemonic and optional passphrase to produce a 512-bit seed via PBKDF2-HMAC-SHA512.

Purpose: human-readable backup
🌳
Key derivation

BIP-32

Defines hierarchical deterministic (HD) wallets: a reproducible tree of child private and public keys is built from a seed.

Purpose: many keys from one seed
🧭
Derivation path

BIP-44

Organizes accounts using a conventional path: m / purpose' / coin_type' / account' / change / address_index. Ethereum uses coin type 60.

Purpose: wallet interoperability
🔑
Public-key crypto

secp256k1

An elliptic curve used by Ethereum. The public key is derived from the private key through scalar multiplication on the curve. The private key signs; the public key verifies.

Purpose: keys and digital signatures
#️⃣
Hashing

Keccak-256

A 256-bit hash function. Ethereum uses it to derive the address from the uncompressed public key, excluding the initial 0x04 byte and taking the last 20 bytes of the hash.

Purpose: fixed-length fingerprint
🔎
Checksum / encoding

EIP-55

Applies uppercase/lowercase casing to hexadecimal letters based on the Keccak-256 hash of the lowercase address. Incorrect casing can flag a typo.

Purpose: typo detection
04 / Key distinctions

Similar words, different functions.

ConceptWhat it meansIn an Ethereum wallet
Key generationCreating an initial private key from a secure random source.Initial entropy contributes to the BIP-39 mnemonic.
Key derivationDeterministically obtaining related keys from a seed or parent key.BIP-32 and BIP-44 build and organize the HD path.
Public-key cryptographyA mathematical relationship links private and public keys and enables verifiable signatures.secp256k1 is used in Ethereum’s key and signature system.
HashingTransforming arbitrary data into a fixed-length digest; it is not reversible encryption.Keccak-256 contributes to address derivation.

EncodingRepresenting data in a conventional format.An address is displayed as a hexadecimal string; EIP-55 specifies its casing.
Why not use a single algorithm?

Because these solve different problems. The BIP standards organize backups and derivation; secp256k1 links keys and signatures; Keccak-256 produces a digest; EIP-55 helps detect transcription errors. A hash cannot replace a signature, and a checksum does not protect a private key.

05 / Historical context

A technology built in layers.

The dates show an approximate historical order and help distinguish foundational cryptography from wallet standards and Ethereum-specific conventions.

1977

RSA

Publication of the RSA system, one of the earliest widely known public-key cryptography techniques.

2001

SHA-2 / SHA-512

The SHA-2 family is standardized by NIST; SHA-512 produces 512-bit digests.

2012

BIP-32

Hierarchical deterministic key derivation is proposed for Bitcoin.

2013

BIP-39

Mnemonic code for generating deterministic-wallet seeds.

2014

BIP-44

A multi-account path convention for HD wallets.

2015

SHA-3

NIST standardizes SHA-3, based on the Keccak design family.

2016

EIP-55

Proposal for mixed-case checksum encoding for Ethereum addresses.

Ethereum

Keccak-256

Ethereum uses the original Keccak-256 variant, not the standardized SHA3-256 function.

Keccak-256 ≠ SHA3-256

Both come from the Keccak family and share the sponge construction, but NIST-standardized SHA3-256 uses a different padding/domain-separation convention. As a result, the same input generally produces different digests. Ethereum addresses require Keccak-256; do not automatically substitute SHA3-256.

06 / Wallet software

Connect the standards to real wallets.

Wallets such as MetaMask, Rabby, Exodus, and Rainbow provide interfaces for creating or importing wallets, managing accounts, and displaying addresses. Their interfaces can help illustrate the practical role of mnemonic backups and derivation paths. For this homework, use only a new test wallet and never share or enter a real recovery phrase into an unfamiliar tool.

What to observe

Look for the recovery phrase or backup process, account creation, the displayed public address, and how one wallet can manage multiple accounts.

What not to confuse

The wallet application is the user interface and key-management software. BIP-39, BIP-32, BIP-44, secp256k1, Keccak-256, and EIP-55 describe distinct standards or cryptographic operations used in the underlying process.

06 / Statistical properties

Entropy, collisions, and checksums.

Security depends mainly on the quality of the initial entropy and the primitives’ resistance to attacks, not on whether the output “looks random.”

128–256 bit

Typical initial entropy for 12- to 24-word BIP-39 mnemonics. The words encode the entropy and a checksum.

256 bit

Keccak-256 digest size. For an ideal hash, collision probability grows according to the birthday principle.

160 bit

Ethereum address length: 20 bytes. The theoretical space contains 2160 addresses.

Entropy and brute-force search

A source with 128 bits of entropy has about 2128 possible states. If the initial choice is uniform and secret, trying every possibility is computationally infeasible with current technology. A phrase invented by hand, however, may have much lower entropy.

Hashing and the birthday bound

For an ideal n-bit hash, finding a generic collision takes about 2n/2 attempts. For Keccak-256, that order of magnitude is 2128. This does not mean it is equally easy to find an input matching a specific digest.

Checksums: useful, not infallible

EIP-55 helps detect many typos through casing. It is neither a digital signature nor an authentication system, and it does not necessarily detect every possible error. Some software accepts all-lowercase addresses without EIP-55 validation.

Determinism and risk

The same mnemonic, passphrase, and path produce the same keys. This is useful for backups, but anyone who obtains the mnemonic and any passphrase can reconstruct the wallet. Do not share them or enter them on unfamiliar websites.

07 / Summary

The answer in one sentence.

The wallet combines key-management standards, an elliptic curve, a hash function, and a checksum convention because each layer solves a different problem: reproducibility, organization, signatures, address derivation, and error detection.
